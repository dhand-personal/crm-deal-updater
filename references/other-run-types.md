# Scheduled runs and calls from other skills

Read this when no rep is in the conversation to approve (a scheduled or
unattended run), or when another skill asks this one for deal
information. In both cases nothing is written to the CRM. Rule 1 in
SKILL.md still applies: writing needs a rep's approval in the
conversation, and a schedule, an earlier approval, or another skill's
request never counts as one.

## Scheduled or unattended runs

Run SKILL.md Steps 1 through 9 and stop. Save the review as a draft for
the rep to open later, and say plainly that nothing was written to the
CRM.

With no one to answer, ask nothing:
- **The deal(s) must be named** in the scheduled request ("the Acme
  renewal"), or be a clear set like "my deals" or "all my open deals"
  (the rep's own open deals, from Step 2). If it's unclear which deals
  are meant, stop and say so in the draft.
- **Snapshot mode needs the snapshot too.** The scheduled request must
  say where to find it (for example a file that gets updated). With no
  snapshot, stop and say so in the draft.
- **Skip every question** the steps would normally ask (which deal, a
  field's unknown current value, "anything to add?"), and list the
  skipped questions at the top of the draft so the rep can answer them
  when they open it.
- **Leave out anything that depends on an answer** (for example an
  Update to a field whose current value is unknown), and note it in the
  draft rather than guessing.

## Being called by another skill

Another skill may ask for a deal's current methodology fields, gaps, or
stage assessment without wanting anything written (for example, a skill
building a proposal that needs the deal's pain and decision process).
Run Steps 1 through 8 read-only, including the content screen, since the
calling skill may put the results somewhere customer-facing, and return
the results.

Return everything found, from every source: unified-communication,
pasted transcripts and emails, rep notes. Label each item by where it
came from:
- **Customer-sourced:** said or written by the customer (a call, a
  customer's email).
- **Internal only:** from internal emails, internal threads, or rep
  notes, with no customer source behind it.

Say plainly that internal-only items are for the seller's use and
shouldn't appear in anything the customer will see. Items held back by
the content screen are not returned.
